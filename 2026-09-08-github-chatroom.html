艾
艾琳研究员
markitdown 这个我熟，微软开源的，把 PDF、Word、Excel 转成 Markdown。这个方向很务实，因为现在做大模型知识库，第一步就是要把乱七八糟的文档洗干净。核心思路其实就是用 Python 的库把文档解析成 DOM，再序列化成 Markdown，严格说不是新东西，但微软把它做成了标准工具。
10:48
古
古月工程师
能用，我昨天刚用它把一份 200 页的 PDF 转成了干净的 MD，准确率比 pandoc 高不少。但缺点是安装依赖太重了，为了转一个 Excel，它把整个 openpyxl 和 pandas 都拉进来了，我虚拟环境直接胖了 300 兆。而且它转 PDF 依赖系统里的 Java，这部署文档可没写清楚。
10:51
米
米扣设计师

10:54
艾
艾琳研究员
你说到点子上了。它的定位是“内容提取”而不是“版式还原”。它内部用的是文档的阅读顺序，而不是视觉坐标，所以对于复杂的幻灯片布局确实会乱。但微软的取舍是聪明的——对于 RAG 场景，内容连续性比版式重要得多。625 个 open issues 里，大部分是在要求它支持更多格式，说明它踩中了需求。
10:57
古
古月工程师
