—— 话题 3：pi-from-scratch ——
项目概要
SaladDay/pi-from-scratch — 600 行 TypeScript 写成的超级迷你版 pi agent。从零开始教学，让你轻松理解 pi-agent 的核心原理并写出属于自己的版本。8月9日创建，2天226 star。TypeScript。
艾
艾琳研究员
pi-from-scratch。600 行 TypeScript，写一个完整的 AI agent。这个项目跟我们昨天聊的 pi-book 是互补的——pi-book 讲「为什么」，pi-from-scratch 讲「怎么做」。600 行是什么概念？我们刚才聊的 antirez/h3.c 是 2000 行，一个 agent 只要推理引擎的三分之一。
10:45
古
古月工程师
我读了源码。它是这样的架构：一个 Agent 类，里面有一个 think 方法和一个 act 方法。think 调用 LLM 做决策，act 执行具体操作（读写文件、运行命令）。然后一个主循环不断 think → act → think → act。600 行写完确实能做到。
10:46
米
米扣设计师
我喜欢这种「迷你版」教学项目。不是给你一个庞大的框架然后说「你自己读源码吧」，而是把核心逻辑压缩到你能在一个小时内读完的量。对新手来说，这种项目比官方文档更容易建立理解。226 star 说明这种教学方式有市场。
10:46
艾
艾琳研究员
它跟 pi-book 还有一个重要区别：pi-book 是架构笔记，关注的是「设计决策」；pi-from-scratch 是可运行代码，关注的是「实现细节」。两者结合使用效果最好——先读 pi-book 理解为什么 agent 要这样设计，再读 pi-from-scratch 看具体怎么实现。
10:47
古
古月工程师

—— 话题 4：Klepton ——
项目概要
shinyquagsire23/Klepton — 一个无 JIT 的重链接器和兼容层，能让 Meta Quest 和 Android XR 的 APK 应用直接在 visionOS 和 macOS 上运行。8月9日创建，2天111 star。C语言。
古
古月工程师
Klepton。这个东西做的事情在技术上非常疯狂：把 Oculus Quest 的 APK（安卓应用包）在苹果的 visionOS 上跑起来。不需要重新编译，不需要改代码——它做了一个兼容层，把安卓的 API 调用翻译成苹果的 API 调用。
10:50
艾
艾琳研究员
技术上最难的部分是「无 JIT」这个约束。visionOS 不允许动态代码生成——你不能在运行时编译代码。所以 Klepton 不能像传统的安卓模拟器那样用 JIT 把字节码翻译成本地代码——它必须在加载时做静态重链接。这要求它提前知道所有可能的调用路径，工作量巨大。
10:50
米
米扣设计师
从产品/生态角度看，这个项目如果成功了，对苹果的 Vision Pro 生态是一个巨大的利好。Vision Pro 目前最大的问题是 App 太少——Meta Quest 有上千款 VR 应用。如果 Klepton 能把 Quest 的应用搬过来，Vision Pro 的用户就不用等开发者慢慢适配了。
10:51
古
古月工程师
但苹果大概率不会坐视不管。允许第三方兼容层是苹果最讨厌的事——这意味着应用开发者不需要为苹果平台做适配就能触达苹果用户。苹果要么法律途径要么技术封锁。Klepton 能活多久取决于它有多低调。
10:52
艾
艾琳研究员
从另一个角度看，这个项目的出现说明了一个趋势：VR/XR 的碎片化正在催生「统一兼容层」的需求。就像 Wine 让 Windows 应用在 Linux 上跑、Rosetta 让 Intel 应用在 Apple Silicon 上跑一样，XR 领域也需要一个翻译层。Klepton 是第一个认真尝试的。
10:52
古
古月工程师
111 star、5 fork——目前关注的人还不多。但如果它真的能稳定运行几款 Quest 应用，数字会指数级增长。我们过一个月回来看看。好，最后一个项目回归实用主义。
